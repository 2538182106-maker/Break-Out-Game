# 联网排行榜 · 部署与接入说明

> **Windows 用户看这里（最短路径）**
>
> | 场景 | 服务器怎么起 | 客户端 `StreamingAssets/server.txt` 填什么 |
> |---|---|---|
> | 单机（游戏和服务器同一台） | 双击 `Server/start_server.bat` | `http://127.0.0.1:8000` |
> | 局域网（游戏在另一台设备） | **右键管理员** `Server/start_server_lan.bat`，记下打印的 IPv4 | `http://那台机器的局域网IP:8000` |
> | 外网（同学在家玩） | 路由器做 8000 端口映射，或跑 ngrok | 公网地址 / ngrok 的 https 地址 |
>
> 服务端脚本：`Server/leaderboard_server.ps1`（零依赖，用 Windows 自带 PowerShell）
> 数据文件：脚本同目录的 `scores.json`（UTF-8 无 BOM，可随时删除重置）
> 客户端状态：右下角 `● 排行榜在线` / `● 服务器暂时离开（离线模式）`，每 8 秒探测一次
>
> 下面的 Linux 章节保留给云服务器部署，Windows 本机不需要看。

> 组成：
> - 服务端：`Server/leaderboard_server.py`（FastAPI + SQLite，单文件）
> - 客户端：`Assets/Script/Game/LeaderboardClient.cs`
> - UI 接入：`Assets/Script/Game/GameUI.cs` → 结算面板自动提交 + 拉 Top 10

## 1. 服务端部署（以 Ubuntu + systemd 为例）

```bash
# 1) 传文件
scp Server/leaderboard_server.py Server/requirements.txt user@你的服务器:/opt/breakout/

# 2) 建环境
cd /opt/breakout
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

### 启动（先手动跑一次，确认能访问）

```bash
export LB_SECRET="自己编一个随机串，比如 7f3a9c1e2d"
export LB_DB="/opt/breakout/leaderboard.db"
uvicorn leaderboard_server:app --host 0.0.0.0 --port 8000
```

浏览器/命令行验证：

```bash
curl http://你的服务器:8000/health
# {"ok":true,"time":...}

curl "http://你的服务器:8000/scores?limit=5"
# {"items":[]}
```

### 常驻运行（systemd）

`/etc/systemd/system/breakout-lb.service`：

```ini
[Unit]
Description=Break Out Leaderboard
After=network.target

[Service]
WorkingDirectory=/opt/breakout
Environment="LB_SECRET=自己编一个随机串"
Environment="LB_DB=/opt/breakout/leaderboard.db"
ExecStart=/opt/breakout/.venv/bin/uvicorn leaderboard_server:app --host 0.0.0.0 --port 8000
Restart=always

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now breakout-lb
sudo systemctl status breakout-lb
```

### 放行端口

云服务器安全组 + 本机防火墙都要开 8000（或你换的端口）：

```bash
sudo ufw allow 8000/tcp
```

> 想用域名 + HTTPS：前面挂 Nginx 反代到 127.0.0.1:8000，用 certbot 签证书。
> **客户端如果走 HTTPS，Unity 端的地址也要改成 https://**

## 2. Unity 端接入（两步）

打开 `Assets/Script/Game/LeaderboardClient.cs`，改顶部两行：

```csharp
private const string DefaultUrl = "http://你的服务器IP:8000";
private const string DefaultSecret = "和服务器 LB_SECRET 完全一致的串";
```

然后在 Play → 让砖块越过 deadline 触发 GAME OVER，结算面板会显示：

```
正在提交分数…
提交成功　当前第 3 名　玩家：玩家A1B2
排行榜 TOP 10
# 1   玩家C3D4   1820 分   (W11 L24)
...
```

服务器没开也不影响游玩：会显示「提交失败（服务器未连接），最高分已保存在本地」。

## 3. 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/health` | 健康检查 |
| GET | `/scores?limit=10` | 前 N 名（按分数降序） |
| POST | `/scores` | 提交分数 |

POST 请求体：

```json
{
  "name": "玩家A1B2",
  "score": 1280,
  "wave": 9,
  "level": 18,
  "kills": 142,
  "checksum": "sha256(name|score|wave|kills|SECRET)"
}
```

返回：`{"ok": true, "rank": 3, "id": 42}`

错误码：
- `400` 签名不匹配 / 数值不合理
- `429` 同一 IP 提交太频繁（60 秒 5 次）

## 4. 防作弊说明（重要）

当前校验能挡住的：
- 随手改本地 JSON 的分数（签名对不上）
- 分数与击杀数明显不匹配（每击杀最多 500 分）
- 刷请求（IP 限频）

**挡不住的**：
- 反编译客户端拿到 `Secret` 后伪造合法签名
- 用内存修改器直接改游戏内分值再提交

真要防，得把「分数计算」搬到服务端（开局发种子、服务端回放校验），那是另一个量级的工作。作为作品集/小范围发布，现在这套够用，但**不要在文档里宣称"防作弊"**，写「基础校验」即可。

## 5. 本机当服务器（最省事，推荐日常用）

游戏和服务器跑在同一台电脑上，**不经过任何网络/NAT**，配置为零。

1. 双击 `Server/start_server.bat`
2. 保持这个黑窗口开着（关掉 = 服务器下线）
3. Unity 里确认 `DefaultUrl = "http://127.0.0.1:8000"`，直接 Play

**联网状态是实时的**：

| 状态 | 表现 |
|---|---|
| 服务器开着 | HUD 右下角 `● 排行榜在线`（绿色），结算自动提交并显示 TOP 10 |
| 服务器关掉 | 8 秒内变成 `● 服务器暂时离开（离线模式）`，结算显示本地记录 TOP 10 |

密钥在 `start_server.bat` 里改（`set LB_SECRET=...`），必须和 Unity 的 `DefaultSecret` 一致。
两边默认都是 `change-me`，所以开箱即用。

**想让同局域网的手机/另一台电脑连**：把 bat 里 A 段注释掉、启用 B 段
（`LB_PREFIX=http://+:8000/` + 防火墙规则），需要**管理员权限**运行，
Unity 里把地址换成 `http://本机局域网IP:8000`。

## 5.2 多机器（局域网：游戏跑在别的电脑上）

**服务器机（你的电脑）**

1. **右键** `Server/start_server_lan.bat` → **以管理员身份运行**
   （必须管理员：监听所有网卡 + 自动加防火墙规则）
2. 窗口里会打印本机所有 IPv4，记下 **192.168.x.x** 或 **10.x.x.x**
3. 窗口保持开着

**客户端机（跑游戏的那台）**

1. 打开 `Assets/StreamingAssets/server.txt`（**打包后在 `游戏名_Data/StreamingAssets/server.txt`**）
2. 第一行改成服务器的局域网地址，第二行密钥：

```
http://192.168.1.10:8000
change-me
```

3. 先在这台机器上用浏览器打开 `http://192.168.1.10:8000/health`，能看到 `{"ok":true}` 再进游戏

> 两台机器必须在**同一个局域网**（同一个路由器/同一个 WiFi）。
> IP 可能因为 DHCP 变化，建议在路由器里给服务器机绑定固定 IP。

**跨公网（不同网络）**：家庭宽带是 NAT，需要二选一——
- 路由器上做 **8000 端口映射**到服务器机（需要路由器管理权限，公网 IP 若会变要配 DDNS）
- 或在服务器机上跑 **ngrok / natapp**，把生成的公网地址填进 `server.txt`

## 6. 常见问题

| 现象 | 排查 |
|---|---|
| Unity 报 `Cannot connect` | 服务器没开 / 安全组没放行 / 端口写错 |
| 返回 400 checksum mismatch | 两边 Secret 不一致（最常见） |
| 返回 429 | 同一 IP 提交超频，等 60 秒 |
| 打包到 Android 后连不上 | 默认禁止明文 HTTP：Player Settings 里勾 **Allow downloads over HTTP**，或改走 HTTPS |
| 中文名字乱码 | 数据库/终端编码问题，接口本身用 UTF-8，正常不会出 |
