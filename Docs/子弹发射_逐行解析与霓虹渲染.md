**正常情况下什么都不用做**：切回 Unity 窗口后，脚本重新编译完成的那一刻，`BreakOutAutoSetup` 会自动检测并执行配置。
Console 里应该出现两行：

```
[BreakOut] 检测到子弹链路未配置，开始自动配置……
[BreakOut] 配置完成：子弹预制体已补 Rigidbody/Trail/Bullet，BulletPool 已挂预制体，……

如果没自动跑（例如当时在 Play 模式、或已经手动改过场景），点菜单手动执行一次：

```
Tools → Break Out → 一键配置发射 + 霓虹发光

它会做四件事（可以重复点，幂等）：

| 步骤 | 内容 |
|---|---|
| ① 材质 | 生成 8 个 URP Lit 自发光材质（子弹 / 玩家 / 死亡线 / 围墙 / 4 色砖块）+ 1 个拖尾材质 |

## 1. Shoot.cs 逐行解析

`Assets/Scripe/Shoot.cs` · 挂在 **Player** 上

> ⚠️ **2026-11-16 修正**：原来用 `OnFire(InputValue)` 记录「是否按住」，会出现「按一下就一直发射」。
> 原因是 `PlayerInput` 的 Send Messages 模式（`PlayerInput.cs:1506`）只转发 `performed`，
> `canceled` 只在 Action 是 **Value** 类型时才转发；本工程 `Fire` 是 **Button** 类型 →
> **松开永远收不到回调** → `isShooting` 卡在 `true`。
> 现在 `Update()` 直接读 `Mouse.current.leftButton.isPressed`，不再依赖事件回调。
> 想改「点一下打一发」：把 `isPressed` 换成 `wasPressedThisFrame`。

| 行 | 代码 | 说明 |
|---|---|---|
| 1–2 | `using UnityEngine;` / `using UnityEngine.InputSystem;` | 前者是 Unity 基础库；后者提供 `InputValue`，没有它 `OnFire` 的参数类型编译不过 |
| 11 | `public class Shoot : MonoBehaviour` | 只有继承 MonoBehaviour 的类才能挂到 GameObject 上、才会被 Unity 每帧调用 Update |
| 14 | `[Tooltip("...")]` | 鼠标悬停在 Inspector 字段上显示的说明文字，纯注释性质，不影响逻辑 |
| 15 | `public Transform firePoint;` | **枪口**。位置决定子弹出生点，`forward` 决定射击方向。用 Transform 而不是 Vector3，是为了能跟着玩家动 |
| 19 | `public float fireRate = 0.5f;` | 两发之间的**间隔**（秒），不是「每秒发数」。公式：每秒发数 = 1 / fireRate |
| 21 | `private float nextFireTime;` | 下一次允许开火的时间戳。`private` = 不出现在 Inspector，属于内部状态 |
| 22 | `private bool isShooting;` | 开火键是否按住。**状态与行为分离**：OnFire 只改状态，Update 决定要不要打 |
| 30 | `public void OnFire(InputValue value)` | 名字必须是 `On` + Action 名。Action 叫 `Fire` → 方法叫 `OnFire`。`public` 是必须的，Input System 反射查找只找 public 方法 |
| 32 | `isShooting = value.isPressed;` | 按下那一帧为 true，松开那一帧变为 false。所以按住会持续 true → 连发 |
| 39 | `private void Update()` | 每帧执行。输入轮询、计时都放这里 |
| 41 | `if (isShooting == false) return;` | 早退出（early return）写法，比嵌套 if 更易读 |
| 42 | `if (Time.time < nextFireTime) return;` | **射速节流**：还没到冷却结束就跳过。`Time.time` 是游戏开始到现在的时间（受 timeScale 影响） |
| 44 | `ShootBullet();` | 真正发射 |
| 45 | `nextFireTime = Time.time + fireRate;` | 重置冷却。放在发射之后，保证这一发的间隔从发射时刻开始算 |
| 53–71 | `ShootBullet()` | 只做「取引用 + 校验 + 交给池子」三件事 |
| 56 | `if (firePoint == null)` | 防御性编程：引用漏拖时给出**明确**报错，而不是每帧一串 NullReference 刷屏 |
| 58 | `Debug.LogError(..., this)` | 第二个参数 `this` 让报错可以点击定位到场景里的具体物体 |
| 63 | `if (BulletPool.Instance == null)` | 单例可能因为没创建 / 已销毁而为空 |
| 70 | `BulletPool.Instance.GetBullet(firePoint.position, firePoint.rotation)` | 位置和旋转交给池子设置。**这里不再重复设置 transform**，避免两处逻辑打架 |

> ⚠️ 为什么必须和 `PlayerInput` 同物体：`m_NotificationBehavior: 0`（Send Messages）只向**同一 GameObject** 上的脚本广播消息。把 Shoot 挪到 Main Camera 上，输入就静默失效了。

## 2. Bullet.cs 逐行解析

`Assets/Scripe/Bullet.cs` · 挂在 **Sphere.prefab** 上

| 行 | 代码 | 说明 |
|---|---|---|
| 14 | `[RequireComponent(typeof(Rigidbody))]` | 声明「我依赖刚体」。加脚本时 Unity 自动补 Rigidbody，从根上杜绝「忘了加刚体」 |
| 19 | `public float speed = 30f;` | 初速度 m/s。30 是手感较好的值（0.25 秒射速下屏幕上一眼能看到 3–4 发） |
| 22 | `public float lifeTime = 2.5f;` | 兜底存活时间，防止子弹飞出场地后永远占着池子 |
| 26 | `public GameObject hitEffectPrefab;` | 命中特效预制体，可以留空 |
| 28–31 | `rb` / `trail` / `lifeTimer` / `returned` | 运行时状态。`returned` 是**防重入锁**，后面会用到 |
| 37–45 | `Awake()` | 只在物体**第一次创建**时执行一次（池子预热时）。适合放「不随复用变化」的初始化 |
| 39–40 | `GetComponent<Rigidbody>()` / `GetComponent<TrailRenderer>()` | 缓存组件，避免在 Update 里反复 GetComponent（性能） |
| 42 | `rb.useGravity = false;` | 关重力，否则子弹会往下掉 |
| 43 | `rb.interpolation = Interpolate;` | 物理按固定步长跑、渲染按帧跑，插值让高速物体看起来不抖 |
| 44 | `CollisionDetectionMode.ContinuousDynamic` | **连续碰撞检测**。默认的 Discrete 在高速下会「一帧跨过整块砖」，也就是隧穿 |
| 51–61 | `OnEnable()` | 每次 `SetActive(true)` 都会执行。**对象池的核心钩子**：所有一次性状态在这里重置 |
| 53–54 | `returned = false; lifeTimer = lifeTime;` | 重置防重入标记和计时器 |
| 56 | `trail.Clear()` | 清空拖尾。不清的话，复用时会从「上一趟飞走的位置」拉一条长线到枪口 |
| 60 | `rb.velocity = transform.forward * speed;` | 沿自身 +Z 给初速度。前提是池子**先**摆好位置和朝向**再**激活（见 BulletPool 第 93–94 行） |
| 67–72 | `OnDisable()` | 每次被收回池子时执行。速度清零，防止下次取出时残留物理状态 |
| 77–83 | `Update()` | 存活倒计时，到 0 就回收 |
| 79 | `if (returned) return;` | 已回收就不再计时，避免重复调用 OnEnable 后计时器错乱 |
| 89–101 | `OnCollisionEnter(Collision)` | 撞到任何带碰撞体的东西都会回调。**必须有 Rigidbody 才会触发**——这就是之前「穿砖而过」的根因 |
| 91 | `if (returned) return;` | 一次撞击可能有多个接触点、可能和多个物体同帧碰撞，这里保证只处理一次 |
| 96 | `collision.GetContact(0)` | 取第一个接触点（位置 + 法线），用来摆特效 |
| 100 | `ReturnToPool()` | 撞什么都回收：砖块、墙、玩家都一样（想区分可以在这里判断 tag） |
| 108–117 | `OnTriggerEnter(Collider)` | 触发器版本的命中。**本工程场景里的砖块勾了 Is Trigger**，只走这里不走 OnCollisionEnter；两道都写更容错 |
| 111 | `if (other.isTrigger == false) return;` | 非 Trigger 的物体交给 OnCollisionEnter，避免同一物体被处理两次 |
| 123–128 | `ReturnToPool()` | 统一回收入口，先上锁再交给池子，双保险 |

### 为什么删掉了 `OnBecameInvisible`

| 问题 | 说明 |
|---|---|
| 触发条件苛刻 | 只在「渲染器从可见变为不可见」时触发一次。相机切换、分屏、Scene 视图都会干扰判断 |
| 会重入 | `SetActive(false)` 本身也会触发 `OnBecameInvisible`，于是 `ReturnBullet` 里再调 `ReturnBullet` → 同一颗子弹入队两次 → 池子里出现重复引用 → 后面「一发变两发」 |
| 不定时 | 子弹如果一直停在画面内（比如卡在角落），就永远不回收 |

现在改成「撞到就回收 + 超时兜底」，行为可预测。

## 3. BulletPool.cs 逐行解析

`Assets/Scripe/BulletPool.cs` · 挂在场景里的 **Bullets** 物体上

| 行 | 代码 | 说明 |
|---|---|---|
| 1 | `using System.Collections.Generic;` | `Queue<T>` 在里面 |

| 21 | `public int poolSize = 30;` | 预热数量。够「同时在场的最多子弹数」即可 |
| 24 | `private readonly Queue<GameObject> pool` | 空闲子弹队列。FIFO：先回收的先被复用，避免某个子弹长期不激活 |
| 30 | `public static BulletPool Instance { get; private set; }` | 单例。`private set` 保证外部只能读不能改 |
| 35–56 | `Awake()` | 场景加载时、所有 Start 之前执行，适合初始化 |

| 48–53 | `bulletPrefab == null` 检查 | 提前报错并 `enabled = false`。旧代码在这里每帧抛 `UnassignedReferenceException` |
| 55 | `Prewarm();` | 一次性造满 |
| 70–79 | `Prewarm()` | 循环 `poolSize` 次生成，生成后立刻失活并入队 |
| 75 | `Instantiate(bulletPrefab, transform, false)` | 第三个参数 `false` = 不保留世界坐标，直接当子物体（Hierarchy 干净、随池子一起移动） |
| 76 | `bullet.SetActive(false)` | 失活 = 不渲染、不 Update、不参与物理 |
| 86–96 | `GetBullet(pos, rot)` | 出池接口 |
| 89–91 | 三元表达式 | 池空就临补一发（它会正常参与后续回收，不会泄漏） |
| 93 | `SetPositionAndRotation` | **必须早于** `SetActive(true)`，因为 OnEnable 要用 transform.forward 算初速度 |
| 94 | `bullet.SetActive(true)` | 激活 → 触发 `Bullet.OnEnable` |
| 104–112 | `ReturnBullet(bullet)` | 回池接口 |
| 107 | `if (!bullet.activeInHierarchy) return;` | **防重入关键**：已失活说明已在池里，直接忽略，杜绝重复入队 |
| 110 | `SetParent(transform, false)` | 收回后统一挂回池子节点，避免 Hierarchy 里子弹散落一地 |

### 对象池 vs 直接 Instantiate/Destroy

| | 直接 Instantiate/Destroy | 对象池 |
|---|---|---|
| 运行时开销 | 每发都分配内存 + 触发 GC | 只有 SetActive 的开关 |
| 突发卡顿 | 有（GC） | 几乎没有 |
| 复杂度 | 低 | 需要管状态重置（就是 OnEnable/OnDisable 那几行） |

## 4. 渲染效果：给每个物体加了什么

### 4.1 材质（URP Lit + 自发光）

| 材质 | 颜色 | 发光强度 | 用在哪 |
|---|---|---|---|
| `BulletGlow.mat` | 青 `(0.25,0.95,1)` | 6.0 | 子弹球体 |
| `Player.mat` | 青绿 `(0.15,1,0.95)` | 3.5 | 挡板 |
| `Deadline.mat` | 红 `(1,0.16,0.28)` | 4.0 | 死亡线（两条） |
| `Wall.mat` | 蓝 `(0.25,0.45,1)` | 1.2 | Cube North / Cube South / Wall |
| `Brick_Neon_*.mat` ×4 | 粉 / 橙 / 绿 / 紫 | 2.2 | Bricks 下所有砖块循环上色 |
| `BulletTrail.mat` | 青白，加法混合 | — | 子弹拖尾 |

**发光是怎么来的**：材质的 `_EmissionColor` 是 **HDR 颜色**（分量可以 > 1），
底色则压到 0.3 倍让暗部足够黑。Bloom 只吃「亮度超过阈值」的像素，所以必须「暗底 + 强发光」才有霓虹感。

### 4.2 拖尾（TrailRenderer）

| 参数 | 值 | 作用 |
|---|---|---|
| `time` | 0.18s | 拖尾长度 = 速度 × 时间 ≈ 30 × 0.18 ≈ 5.4 米 |
| `startWidth` / `endWidth` | 0.18 / 0 | 头粗尾细，收成尖 |
| `colorGradient` | 青白 → 蓝 → 紫，透明度 1 → 0 | 有「余晖」感 |
| `numCapVertices` | 4 | 圆润接头 |

> 材质用了加法混合（Additive），叠加在深色背景上会越叠越亮，配合 Bloom 很出效果。

### 4.3 后处理（`Assets/Settings/SampleSceneProfile.asset`，Global Volume）

| 效果 | 参数 | 说明 |
|---|---|---|
| Bloom | 阈值 0.85 / 强度 1.6 / 散射 0.72 / 冷白 tint | 阈值从默认 1.0 降下来，让中等亮度也溢光 |
| ColorAdjustments | 饱和度 +18 / 对比度 +10 | 让霓虹色更「脏得起来」，画面更通透 |
| Vignette | 强度 0.32 | 压暗四角，注意力集中在场地中央 |

> 前提：相机上要有 `Post Process` / URP 的 Volume 生效（本工程 Main Camera 是 URP 相机，Global Volume 已存在，无需额外操作）。

## 5. 参数怎么调（速查）

| 想要的效果 | 改哪里 |

## 6. 排查清单

| 现象 | 检查顺序 |
|---|---|
| 点左键没反应 | ① Shoot 是否和 PlayerInput 同物体 ② Console 有无 `firePoint 未赋值` ③ 是否在 Play 模式 |
| **按一下鼠标却一直连发** | `Fire` 是 Button 类型，Send Messages 不转发 `canceled` → 松开收不到。已改为直接读 `Mouse.current.leftButton.isPressed` |
| 有子弹但不飞 | 预制体是否挂了 `Bullet` + `Rigidbody`（跑一次菜单即可） |
| 子弹穿过砖块 | 预制体 Rigidbody 是否 `ContinuousDynamic`；砖块 Collider 是否 `Is Trigger`（**本工程 Brick 被勾了 IsTrigger，记得取消**） |
| 子弹堆在枪口 | `Bullet.speed` 是否为 0；`Shoot.fireRate` 是否过小 |
| 池子报未赋值 | `BulletPool.bulletPrefab` 是否指向 `Sphere.prefab` |
| 没有发光 | 材质 `Emission` 是否勾选；Volume 里 Bloom 是否 Active；相机是否 URP |
| 拖尾是一坨 | 拖尾材质着色器不支持顶点色，换成 `Universal Render Pipeline/Particles/Unlit` |

> ⚠️ 特别注意（已经帮你处理了）：场景里 `Bricks` 下那块砖的实例上，`BoxCollider.Is Trigger` 被勾选了。
> Trigger 碰撞体不会触发 `OnCollisionEnter`，只会触发 `OnTriggerEnter`，子弹会直接穿过去。
> 现在的处理是双保险：一键配置脚本会**自动取消**砖块的 Is Trigger，`Bullet` 里也补了 `OnTriggerEnter` 兜底。

## 7. 数据流总览

```
鼠标左键
  → InputSystem_Actions "Fire" Action
    → PlayerInput (Send Messages)
      → Shoot.OnFire(InputValue)     记录 isShooting
        → Shoot.Update()             时间节流 fireRate
          → Shoot.ShootBullet()
            → BulletPool.GetBullet(firePoint.position, firePoint.rotation)
              → 从 Queue 取一个 → 摆位置 → SetActive(true)
                → Bullet.OnEnable()  重置状态 + 给初速度
                  → Rigidbody 物理飞行
                    ├─ OnCollisionEnter → 回收
                    └─ lifeTime 到 → 回收
                      → BulletPool.ReturnBullet → SetActive(false) → 回队列
```
