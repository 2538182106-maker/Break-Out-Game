# 美漫描边渲染 · 四个文件逐行解析

> 工程：`D:\unity project\Break Out Game`（Unity 2022.3.62 + URP 14.0.12）
> 新增文件：
> - `Assets/Shader/ComicToon.shader`（约 205 行）——物体着色 + 反向外壳描边
> - `Assets/Shader/ComicInk.shader`（约 161 行）——全屏漫画化后处理
> - `Assets/Script/Rendering/ComicInkFeature.cs`（约 100 行）——把后处理插进 URP
> - `Assets/Editor/ComicModeSetup.cs`（约 366 行）——一键切换材质/管线

---

## 0. 先看这张图：四个文件怎么串起来

```
 每帧渲染流程（URP）
 ├─ 画不透明物体 ──────────► ComicToon.shader 的 Pass 1（卡通着色）
 │                              └─ Pass 2（反向外壳描边，只画背面）
 │
 ├─ 深度图 _CameraDepthTexture（由 URP 生成，ComicInkFeature 申请）
 │
 ├─ ComicInkFeature.Execute()
 │     └─ 用 ComicInk.shader 画一张全屏 quad：
 │          读 { 颜色图 + 深度图 } → 算墨线 → 量化色阶 → 撒网点 → 叠纸纹
 │
 └─ 后处理（Bloom / Vignette ...）
```

对应关系：

| 文件 | 跑在哪 | 谁调用它 |
|---|---|---|
| ComicToon.shader | GPU，每个物体 | Unity 的渲染循环（材质挂在 MeshRenderer 上） |
| ComicInkFeature.cs | CPU（C#），每帧一次 | URP 渲染器（Renderer Feature 机制） |
| ComicInk.shader | GPU，全屏一次 | ComicInkFeature 里的 `cmd.Blit` |
| ComicModeSetup.cs | 只在编辑器 | 你点菜单 |

## 1. 前置知识对照表（你现在还没学到的是哪几块）

| 文件里出现的概念 | 属于什么知识 | 你的计划里在哪一课 |
|---|---|---|
| `float3` / `dot` / `normalize` / `lerp` / `smoothstep` | 向量数学 + HLSL 内置函数 | 3B1B 线代（已完成）+ GAMES101 L1–2（12 月） |
| 顶点/片元着色器、`POSITION`/`NORMAL` 语义 | 渲染管线阶段 | GAMES101 L5–6 光栅化（12 月） |
| `NdotL` 半兰伯特、`SampleSH` 环境光 | 光照模型 | 《Unity Shader 入门精要》第 6 章（W8–W9） |
| `CBUFFER` / SRP Batcher | URP 渲染管线特性 | P1 进阶（2027.01–02） |
| `Cull Front` 反向外壳 | 描边技巧（本计划的 W11 预研项） | W11「描边 shader 预研」+ P1「风格化 Shader 合集」 |
| `ScriptableRendererFeature` / `CommandBuffer` / `Blit` | URP 自定义渲染 Pass | P1 之后，属于「管线」方向 |
| 深度图、Roberts Cross 边缘检测 | 后处理 / 图像处理 | P1–P2 |

**结论：这四个文件横跨了你计划里的 W8（第一个 shader）到 P1（风格化合集）的内容**，
现在看不懂是正常的。建议的读法：先只看 ComicToon.shader 的 Pass 1，把它当成「一个会算光照的公式」。

### 2.3 Pass 1：卡通着色（第 44–134 行）

| 行 | 代码 | 解释 |
|---|---|---|
| 44 | `Pass` | 一个 Pass = 一次绘制。这里第一次绘制负责「颜色」 |
| 46 | `Name "ComicToon"` | Pass 名字，方便调试/在其他地方引用 |
| 47 | `Tags { "LightMode"="UniversalForward" }` | **最关键的一行**：URP 靠 LightMode 决定这个 Pass 在哪个阶段画。`UniversalForward` = 主着色阶段 |
| 49 | `HLSLPROGRAM` | 后面才是真正的 HLSL 代码，不是 ShaderLab |
| 50–51 | `#pragma vertex vert` / `#pragma fragment frag` | 指定入口函数名 |
| 52 | `#pragma multi_compile_instancing` | 开启 GPU Instancing 的多变体编译 |
| 55 | `#include ".../Core.hlsl"` | 引入 URP 基础函数：坐标变换、常用数学 |
| 57 | `#include ".../Lighting.hlsl"` | 引入光照函数：`GetMainLight()`、`SampleSH()` |
| 60–70 | `CBUFFER_START(UnityPerMaterial) ... END` | 材质参数的常量缓冲。**必须**把所有属性放进来，SRP Batcher 才能把相同 shader 的物体合批 |
| 73–79 | `struct Attributes` | 顶点输入结构：`positionOS`（物体空间坐标）、`normalOS`（物体空间法线）、实例 ID |
| 81–87 | `struct Varyings` | 顶点输出/片元输入：`positionCS`（裁剪空间位置，语义必须是 `SV_POSITION`）、`normalWS`、`positionWS` |
| 89–100 | `vert()` | 顶点着色器：把顶点从物体空间变换到裁剪空间，把法线转到世界空间 |
| 91 | `Varyings o = (Varyings)0;` | 结构体清零。某些平台不初始化输出会读到垃圾值 |
| 95 | `GetVertexPositionInputs(...)` | URP 的封装：一次算好 positionCS / positionWS / positionVS |
| 96 | `o.positionCS = pos.positionCS;` | 屏幕位置（管线靠它把三角形光栅化） |
| 98 | `TransformObjectToWorldNormal(...)` | 法线变换不能直接用模型矩阵（要用法线矩阵），URP 封装好了 |

### 2.4 片元着色（第 102–132 行）——整段的核心

| 行 | 代码 | 解释 |
|---|---|---|
| 102 | `half4 frag(Varyings i) : SV_Target` | 片元着色器：每个像素执行一次，返回值就是要写的颜色 |
| 104 | `normalize(i.normalWS)` | 顶点属性插值后长度不再是 1，必须重新归一化 |
| 105 | `_WorldSpaceCameraPos - i.positionWS` | 从物体指向相机的向量（视线方向 V） |
| 107 | `GetMainLight()` | 取场景主平行光（Directional Light），返回方向和颜色 |
| 108 | `dot(N, mainLight.direction)` | **兰伯特点积**：两向量夹角越小越接近 1，即越正对光越亮 |
| 112 | `NdotL * 0.5 + 0.5` | **半兰伯特**：把 [-1,1] 拉到 [0,1]，背光面不会死黑 |
| 114 | `smoothstep(_Step-_StepSoft, _Step+_StepSoft, halfLambert)` | **硬阶**：把连续亮度变成 0 或 1 的台阶。`_StepSoft` 越小，"台阶"越硬 |
| 117–119 | `albedo` / `lit` / `shadow` | 受光色 = 基础色；阴影色 = 基础色 × 阴影色（乘算能保持色相统一） |
| 120 | `lerp(shadow, lit, ramp)` | 用 ramp(0/1) 在阴影色和受光色之间插值 → 出现两个色块 |
| 123 | `SampleSH(N) * albedo * 0.25` | 环境光（球谐光照），强度故意压到 0.25，避免冲淡色块 |
| 126 | `1 - saturate(dot(N, V))` | 菲涅尔近似：正对相机为 0，边缘为 1 |
| 127 | `pow(rim, _RimPower)` | 控制边缘光宽度 |
| 128 | `smoothstep(0.55, 0.65, rim)` | 把边缘光也硬切，保持"块状"，不要柔和渐变 |
| 131 | `return half4(color, 1.0)` | alpha 固定 1（不透明） |

### 2.5 Pass 2：反向外壳描边（第 143–200 行）

| 行 | 代码 | 解释 |
|---|---|---|
| 143–147 | `Pass` / `Name "Outline"` / `Cull Front` / `ZWrite On` | **Cull Front 是灵魂**：正常渲染剔除背面、只画正面；这里反过来只画背面 |
| 149–153 | `HLSLPROGRAM` + 只 include `Core.hlsl` | 描边不需要光照，省掉 Lighting.hlsl，编译更快 |
| 155–165 | `CBUFFER` | 必须和 Pass 1 **完全一致**（SRP Batcher 要求同一 shader 的所有 Pass 共用布局） |
| 167–171 | `Attributes` | 只需要位置和法线 |
| 173–176 | `Varyings` | 只需要 `positionCS` |
| 182 | `TransformObjectToWorld` | 顶点位置转世界空间（要在这里外扩，所以用世界空间） |
| 183 | `TransformObjectToWorldNormal` | 法线转世界空间并归一化 |
| 187 | `distance(posWS, _WorldSpaceCameraPos)` | 到相机的距离，用来做线宽补偿 |
| 189 | `posWS += nWS * _OutlineWidth * dist * 0.6` | **外扩**：沿法线把顶点推开，距离越远推得越多，屏幕线宽才一致 |
| 191 | `TransformWorldToHClip` | 世界 → 裁剪空间 |
| 195–198 | `fragOutline` | 直接返回描边色，不做任何光照 |
| 204 | `FallBack "Universal Render Pipeline/Unlit"` | 兜底：万一 URP shader 编译失败，用一个安全的 fallback |

### 这个 shader 的参数怎么调

| 想要 | 改 |
|---|---|
| 明暗分界更靠上（亮部更多） | `_Step` 调小 |
| 完全没有渐变（最硬） | `_StepSoft` 调到 0.001 |
| 描边更粗 | `_OutlineWidth` 调大（0.05 → 0.1） |
| 描边更黑 | `_OutlineColor` 调成 (0,0,0,1) |
| 边缘光更亮/更细 | `_RimStrength` / `_RimPower` |

## 3. ComicInk.shader 逐行

### 3.1 声明与设置（第 12–43 行）

### 3.2 顶点与工具函数（第 45–95 行）

| 行 | 代码 | 解释 |
|---|---|---|
| 45–47 | `HLSLPROGRAM` + `#pragma vertex/fragment` | 入口 |
| 49 | `#include ".../Core.hlsl"` | URP 基础库（含 `GetFullScreenTriangleVertexPosition`） |
| 51 | `#include ".../DeclareDepthTexture.hlsl"` | 提供 `SampleSceneDepth()`，用来读 `_CameraDepthTexture` |
| 54–56 | `TEXTURE2D_X(_BlitTexture); SAMPLER(sampler_LinearClamp); float4 _BlitScaleBias;` | 源图叫 **`_BlitTexture`**（不是 `_MainTex`），由 `Blitter.BlitTexture` 绑定 |
| 58–68 | `CBUFFER` | 材质参数 |
| 72–75 | `Attributes { uint vertexID : SV_VertexID; }` | **全屏三角形**：Blitter 用 DrawProcedural 画 3 个顶点，没有网格，只能靠 vertexID 算位置 |
| 77–81 | `Varyings` | 位置 + UV |
| 83–90 | `vert()` | `GetFullScreenTriangleVertexPosition/TexCoord` 生成铺满屏幕的三角形 |
| 92–95 | `Luma(float3)` | 亮度公式：`0.2126R + 0.7152G + 0.0722B`（人眼对绿最敏感，所以绿色权重最大） |

### 3.3 片元（第 97–160 行）

| 行 | 代码 | 解释 |
|---|---|---|
| 97 | `half4 frag(...)` | 每个屏幕像素执行一次 |
| 99 | `float2 uv = i.uv` | 当前像素的屏幕 UV |
| 101 | `_Thickness / _ScreenParams.xy` | 把"像素"换算成 UV 偏移，保证 1080p 和 4K 下线宽一致 |
| 105–108 | `SampleSceneDepth(...)` + `LinearEyeDepth` | 取 4 个**对角**采样点的深度。`LinearEyeDepth` 把非线性的深度值转成真实距离（米） |
| 111 | `min(abs(d0-d1), abs(d2-d3))` | Roberts Cross：两组对角差取最小 → 抗噪，只对真正的"边界"敏感 |
| 113 | `smoothstep(_DepthThreshold, _DepthThreshold*2, edgeDepth)` | 把连续差值压成 0/1 的硬线 |
| 118–121 | 再取 4 个点的颜色 | 用来算亮度差 |
| 123 | `min(abs(Luma(c0)-Luma(c1)), ...)` | 亮度差：能抓到深度抓不到的"贴纸式"色差边界 |
| 126 | `max(edgeDepth, edgeLuma) * _EdgeStrength` | 两种边缘取并集，再整体调强度 |
| 129 | 取中心像素颜色 | 这是要输出的底图 |
| 133 | `floor(col * N + 0.5) / N` | **色阶量化**：把 0~1 切成 N 档，去掉连续渐变 |
| 136 | `uv * _ScreenParams.xy` | 换成像素坐标，网点才能在屏幕上均匀 |
| 138–139 | 旋转 45° 的矩阵 | 印刷网点的经典角度，避免和像素网格对齐产生摩尔纹 |
| 140 | `frac(rot / _HalftoneScale) - 0.5` | 把屏幕切成一个个格子，得到"格子内相对坐标" |
| 141 | `length(cell)` | 到格子中心的距离 → 决定这个像素在不在圆点里 |
| 144 | `saturate(1 - luma) * 0.62` | 越暗 → 半径越大 → 点越大（这就是半调网点的核心逻辑） |
| 145 | `smoothstep(radius, radius-0.08, dist)` | 距离小于半径 = 在点内，返回 1 |
| 146 | `dots *= 1 - smoothstep(0.7, 1, luma)` | 亮部不铺点，避免糊成一片 |
| 148 | `col *= 1 - dots * _HalftoneStrength` | 网点处压暗（模拟油墨堆积） |
| 152 | `frac(sin(dot(px, float2(12.9898, 78.233))) * 43758.5453)` | 经典伪随机 hash，做纸张颗粒 |
| 153 | `col *= 1 - grain * _PaperStrength` | 叠颗粒 |
| 156 | `lerp(col, _InkColor.rgb, edge)` | **最后**叠墨线，保证线是干净的纯色 |
| 158 | `return half4(col, 1.0)` | 输出 |

## 7. 可能遇到的坑

| 现象 | 原因 / 解法 |
|---|---|
| 画面全黑或全白 | 深度图没打开。URP Asset 勾 `Depth Texture`，或确认 Feature 的 `ConfigureInput(Depth)` 生效 |
| 全屏灰底 + 网点、游戏画面消失 | 相机在画 backbuffer，而 backbuffer 不能被采样。解法：`ConfigureInput(Depth \| Color)` + `Blitter.BlitTexture`（已在代码里） |
| **地面全黑** | 色阶量化把暗色压成 0：`floor(x*N+0.5)/N` 在 N=6 时会把 <0.083 的颜色直接变黑。解法：`_BlackLift` + `_PosterizeStrength`（已加） |
| **物体像平涂色块、没有体积** | 俯视相机下所有竖直面 `dot(N,V)≈0`，边缘光被算成满值 → 所有侧面发白。解法：rim 乘 `saturate(NdotL)`，强度默认降到 0.3（已改） |
| **描边粗得离谱** | 外扩量 = `_OutlineWidth × 距离 × 0.6`，本场景 ≈ 0.27 米（物体的 27%）。改成 ×0.15 ≈ 0.07 米（已改） |
| 完全没有墨线 | `ComicInkFeature` 没挂到当前 Renderer；或 `ComicInk.mat` 没赋给 feature |
| 网点在移动时有摩尔纹 | `Halftone Scale` 调小一点（点更大），或关掉 |
| 编辑时看到效果，Play 后没了 | Feature 的 `applyInSceneView` 只影响 Scene 视图；Play 后跑的是 Game 视图，正常 |
| 切回霓虹后还有墨线 | Feature 只是 `SetActive(false)`，如果还残留说明有第二个 Feature 实例 |

## 8. 修正记录（2026-11-16 下午）

第一版跑出来是「灰底 + 网点」，修完采样后又暴露出三个观感问题，已全部修掉：

| 问题 | 根因 | 改动 |
|---|---|---|
| 全屏灰底 + 网点 | 相机颜色目标不能被采样 + shader 采的是 `_MainTex` | `ConfigureInput(Depth \| Color)`；`Blitter.BlitTexture` + `_BlitTexture` + 全屏三角形 |
| 地面全黑 | `posterize` 把 < 1/(2N) 的暗色压成 0 | 新增 `_PosterizeStrength`（默认 0.7）、`_BlackLift`（默认 0.6），最暗档兜底 |
| 物体像平涂色块 | 俯视下所有竖直面 rim 满值（`dot(N,V)=0`） | `rim *= saturate(NdotL)`，`_RimStrength` 默认 0.8 → 0.3 |
| 描边过粗 | 外扩系数 0.6 → 约 0.27 米 | 系数改为 0.15，约 0.07 米 |
| 地面没有漫画色 | 地面仍用 `Plane.mat` | 新增 `ComicFloor` 材质，切换菜单会把它赋给 `Plane` / `Main Plane` |
| **描边在拐角断开 / 横竖线粗细不一** | 对角 4 采样（Roberts Cross）在 90° 拐角漏检，且方向响应不一致 | 改成 **3×3 Sobel**（8 邻域 + 1-2-1 权重），加 `_CornerBoost` 拐角补强 |
| 需求变更 | 用户要的是「霓虹 + 描边」，不是整体漫画化 | 新增菜单「霓虹 + 描边：开启/关闭」：材质不动，只开描边层；印刷参数全设 0；描边改画在**后处理之后**（不被 Bloom 糊掉） |
