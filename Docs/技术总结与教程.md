# Break Out Game —— 技术总结与上手教程

> 版本：1.2.3.4　引擎：Unity 2022.3.62f3c1 + URP 14.0.12　输入：Input System 1.14.2
> 代码规模：48 个 C# 脚本 / 约 9000 行（游戏逻辑 35 个 + 渲染 1 个 + 基础玩法 4 个 + 编辑器 8 个）

---

## 0. 项目速览

一个「打砖块 + Roguelike 技能构筑」的完整小项目：连续射击打砖块、升级三选一、技能叠加、Boss 波次、联网排行榜、服务器热更新配置。

| 模块 | 关键技术 |
|---|---|
| 玩法 | 状态机、事件驱动、对象池、技能等级系统 |
| 表现 | URP + Bloom、程序化 uGUI、程序化音效、屏幕震动、伤害数字 |
| 数值 | 全部参数化到 `config.json`，64 个字段远程可调 |
| 网络 | UnityWebRequest + PowerShell `HttpListener`（另有 Python FastAPI 版） |
| 发布 | 版本号、应用图标、公告、强制更新、内网穿透 |

### 1.1 三层结构

```
┌───────────── 表现层 ─────────────┐
│ GameUI / MainMenuUI / SettingsUI │  uGUI，全部运行时构建，无 prefab
│ NoticeUI / BootGate / PerfHud    │
└──────────────┬──────────────────┘

┌──────────────▼──────────────────┐
│ 逻辑层 GameManager（状态机）      │
│  PlayerStats（数值）             │
│  UpgradeDatabase（技能表）        │
└──────────────┬──────────────────┘
               │ 数据
┌──────────────▼──────────────────┐
│ 数据层 GameConfig / LeaderboardClient │
│  config.json / scores.json       │
└─────────────────────────────────┘
```

### 1.2 状态机

```csharp
public enum GameState { Menu, Playing, Paused, UpgradeSelecting, GameOver }
```

所有「谁能动、谁能射击、谁能点」都靠它判断：

```csharp
// 射击：只在 Playing 时开火
if (GameManager.Instance != null && GameManager.Instance.State != GameState.Playing) return;

// HUD：菜单状态整块关掉（Overlay 画布会盖住相机空间菜单）
canvas.enabled = gm.State != GameState.Menu;
```

**经验**：状态机是这类游戏最划算的设计——所有"卡住""重复触发""UI 遮挡"的 bug 一根针就能扎住。

### 1.3 事件驱动

`GameManager` 只广播事件，不直接操作 UI：

```csharp
public event Action<int> OnScoreChanged;
public event Action OnUpgradeRequested;
public event Action OnGameOver;
public event Action OnBossSpawned;
```

UI 在 `Awake` 订阅，`OnDestroy` 反订阅。

> ⚠️ **踩过的坑**：`OnChanged` 曾经只在"分数变化"时触发，导致强化进度条只有打死砖块才刷新 → 看起来"一跳一跳"。UI 里需要每帧变化的元素（进度条/计时器）必须自己逐帧刷新，不能依赖事件。

## 2. 渲染与视觉

### 2.1 URP + Bloom

- Bloom 阈值 **1.11**、强度 **2.2**：任何 `_EmissionColor > 1.11` 的自发光都会泛光。
- 所以「发光」的写法是 **颜色 × 强度**，不是调亮 BaseColor：

```csharp
mpb.SetColor("_BaseColor", color * 0.35f);                    // 底色压暗
mpb.SetColor("_EmissionColor", color * 1.6f * opacity);        // 发光超阈值 → Bloom
```

### 2.2 MaterialPropertyBlock（MPB）

同一个材质、不同颜色 → 用 MPB，**不产生材质实例**：

```csharp
renderer.GetPropertyBlock(mpb);
mpb.SetColor("_EmissionColor", color * intensity);
renderer.SetPropertyBlock(mpb);
```

> ⚠️ **代价**：MPB 不同 → **打断合批**。852 个特效方块各写一次 MPB = 852 次 draw call。
> **解决**：限制同时存在的数量（见 5.3）。

### 2.3 全屏描边（Renderer Feature）

`ComicInkFeature : ScriptableRendererFeature` —— 用 Sobel 算子在屏幕空间做边缘检测，需要开 Depth Texture。

**教程**：

1. 新建 `ScriptableRendererFeature` + `ScriptableRenderPass`
2. `ConfigureInput(ScriptableRenderPassInput.Depth)` 拿到深度
3. `Blit` 到临时 RT，在 Shader 里做卷积
4. 把 Feature 加到 URP Asset 的 Renderer 上

**踩过的坑**：

| 问题 | 原因 | 解决 |
|---|---|---|
| 打包报 `URP/Lit too many variants (1327104)` | Always Included Shaders 里放了 URP/Lit | 移除，靠场景引用自动收集 |
| 打包后材质变粉 | 自定义 Shader 未被打包 | 材质放 Resources 或场景引用 |

## 3. 程序化 UI

**这个项目没有任何 UI prefab**，所有界面都是代码生成。好处：版本管理干净、参数全在代码里；坏处：坐标要算。

### 3.1 九宫格圆角贴图

```csharp
// 64×64 的画布，程序化画圆角矩形，border = 16 做九宫格
public static Sprite Rounded(int radius) { /* 缓存，只生成一次 */ }
```

配合 `Image.type = Image.Type.Sliced`，任意拉伸都不糊。

### 3.2 中文字体

```csharp
Font.CreateDynamicFontFromOSFont("Microsoft YaHei", 40);
```

免去 20MB 字体资源，但有两个限制：
- 只支持这个字体里有的字形（颜文字 `(ᗜ ‸ ᗜ)` 里 `ᗜ` 在别的 Unicode 区块 → 显示不出来）
- 小字号 + 非整数缩放会发虚

### 3.3 文字发虚的四个原因（按命中率排序）

| 原因 | 解决 |
|---|---|
| **Outline 描边** | 4 份偏移 ±1.5px 的半透明拷贝会糊在小字号上 → 正文关掉或降到 ±1px |
| Canvas 未开 Pixel Perfect | `canvas.pixelPerfect = true` |
| CanvasScaler 非整数缩放 | 用 1920×1080 参考分辨率，尽量在整数倍分辨率下运行 |
| 动态字体小字号 | 最小字号提到 22 |

### 3.4 Canvas 层级表

| sortingOrder | 界面 |
|---|---|
| 300 | PerfHud（F1 调试） |
| 250 | BootGate（启动连接） |
| 210 | 公告 |
| 205 | 设置 |
| 200 | 主菜单（相机空间） |
| 100 | 游戏 HUD |
| 90 | 伤害数字 / 菜单背景砖块 |

**教程：如何判断遮挡问题**

1. 把所有 Canvas 的 sortingOrder 列出来排个序
2. 每个弹窗问三个问题：**盖住谁？被谁盖住？打开时后面的按钮点得到吗？**
3. 最后一道防线：遮罩 Image 的 `raycastTarget = true`

### 3.5 滚动视图 + 滑条

```csharp
// 关键：视口必须有一张能接射线的图，否则滚轮事件发不出去
Image vp = viewportGo.AddComponent<Image>();
vp.color = new Color(1, 1, 1, 0);   // 全透明
vp.raycastTarget = true;
```

滚轮灵敏度（新输入系统）：

| 设置 | 一格滚轮 |
|---|---|
| 45 | 5400px（直接冲到底）❌ |
| 1 | 120px ✅ |
| 0.1 | 12px（本项目采用） |

> 原因：新 Input System 的 `Mouse.scroll` 一格就是 **±120**，老输入是 ±1。

### 3.6 滑条（Slider）

Unity 的 `Slider` 需要三件套：

```csharp
slider.fillRect = fillRect;       // 填充块
slider.handleRect = handleRect;   // 手柄
slider.targetGraphic = handle;    // 可交互
```

> ⚠️ **坑**：滑条根节点如果没有 Graphic，点击滑轨不会跳值（只有拖手柄有效）。给它挂一张 `alpha = 0` 的 Image 即可。

## 4. 玩法系统

### 4.1 技能系统

```csharp
public enum SkillId { MultiShot, Pierce, Explosion, Dot, Buff, Emp, XpGain, RapidFire, Crit, CritDamage, Lethal, Slow, Freeze, Shield }
```

- 每个技能在 `PlayerStats` 里是一个 `[Range(0,5)] public int` 字段
- **所有系数都是字段**（不是常量），这样才能被 `config.json` 覆盖
- 卡面文案**从 PlayerStats 实时读取**，配置改了文案自动跟着变

```csharp
// 反例（早期写法）：文案写死
offer.Desc = "暴击率 +20%";

// 正例（现在）：从数值读，格式化后显示
offer.Desc = $"暴击率 +{critStep * 100f:0}%（{prev*step*100}% → {tier*step*100}%）";
```

> **重要**：新版把 `{x:0}` 改成了 `{x:0.#}` —— 因为冰冻概率是 0.5%/阶，用 `{0}` 会显示成 "0%" 或 "1%"，玩家看到"0% 概率"直接懵。

### 4.2 失败线与护盾

- 砖块 `pos.x <= deadlineX` → 判定失败
- 有护盾时：砖块**被打碎**，护盾 -1

```csharp
if (pos.x <= deadlineX)
{
    if (DeadlineShield.TryBlock()) { /* 碎砖特效 + 护盾-1 */ Die(); return; }
    GameManager.Instance?.GameOver();
}
```

### 4.3 Boss 控制抗性

Boss 血厚、体型大，如果没有抗性会被"多重子弹 + 冰冻"永久控死：

```csharp
public static float BossControlCooldown = 0.5f;   // 可由 config 覆盖

// 冰冻
if (isBoss) { if (Time.time < nextBossFreezeTime) return; nextBossFreezeTime = Time.time + 0.5f; }

// 致命一击（返回 false 表示没生效，调用方退回普通伤害）
if (isBoss) { if (Time.time < nextBossLethalTime) return false; nextBossLethalTime = Time.time + 0.5f; }
```

## 5. 性能工程

> 这一节是整个项目**最有价值**的部分，因为所有优化都是**用 F1 面板量出来的**，不是猜的。

### 5.1 先做可观测性，再优化

`PerfHud`（F1 开关）显示：FPS、帧时间、子弹数、砖块数、电磁圈数、特效方块数、时间缩放。

实测数据：

| 场景 | FPS | 特效方块 | 电磁圈 |
|---|---|---|---|
| 开局 | 301 | 0 | 2 |
| 34 波 | 61 | **435** | 68 |
| Boss 战 | 56 | **852** | 61 |

→ 瓶颈一目了然：**852 个渲染器**。

### 5.2 六类优化手法

| # | 手法 | 例子 | 收益 |
|---|---|---|---|
| 1 | **对象池** | 子弹 300、特效方块 180、经验球/电磁圈/冲击波 | 消 GC |
| 2 | **数量封顶** | 伤害数字 20 个、特效方块 180 个、可见电磁球 12 个 | 削 draw call |
| 3 | **零分配物理查询** | `Physics.OverlapSphereNonAlloc` + 复用 HashSet | 后期每秒省 1200 次分配 |
| 4 | **错帧** | 电磁圈 tick 随机偏移 | 消除同帧集中查询的尖峰 |
| 5 | **降频** | 电磁发光每 4 帧写一次 MPB | 省 1.8 万次/秒 |
| 6 | **事件驱动代替每帧** | 砖块血条只在 `TakeDamage` 时刷新 | 省 1800 次调用/秒 |

### 5.3 典型代码：零分配范围伤害

```csharp
private static readonly Collider[] buffer = new Collider[128];
private static readonly HashSet<Brick> damaged = new HashSet<Brick>();

public static void DamageArea(Vector3 center, float radius, float damage, ...)
{
    int n = Physics.OverlapSphereNonAlloc(center, radius, buffer);   // ← 不分配
    damaged.Clear();                                                 // ← 复用集合
    for (int i = 0; i < n; i++) { ... }
}
```

### 5.4 最隐蔽的 bug：延迟销毁的碰撞体

```csharp
GameObject go = GameObject.CreatePrimitive(PrimitiveType.Sphere);
Object.Destroy(go.GetComponent<Collider>());   // ← 帧末才生效！
```

**这一帧里碰撞体仍然有效**。子弹撞上去被当成"墙"消耗 → **子弹凭空消失 / 卡在 Boss 那一带 / 打不出去**。

```csharp
// 正确写法
Collider col = go.GetComponent<Collider>();
if (col != null) { col.enabled = false; Object.Destroy(col); }
```

再加一道保险：子弹侧直接忽略特效类碰撞体。

```csharp
if (other.GetComponentInParent<FxBit>() != null
    || other.GetComponentInParent<FxSphere>() != null
    || other.GetComponentInParent<EmpField>() != null
    || other.GetComponentInParent<XpOrb>() != null) return;
```

### 5.5 性能优化排查流程（可复用）

1. **打开可观测面板**（本项目 F1）
2. **找数量爆炸的那一项**（852 个特效方块）
3. **问：这些对象必须同时存在吗？** → 不需要就封顶
4. **问：每帧都必须更新吗？** → 不需要就降频/事件驱动
5. **问：必须分配内存吗？** → 用 NonAlloc / 复用容器
6. **改完再量一次**

## 6. 音频

### 6.1 程序化音效（零资源）

`SoundFx` 用代码合成波形（正弦 + 噪声 + 包络），生成 `AudioClip`，用 4 个 `AudioSource` 轮播：

```csharp
s.PlayOneShot(clip, Mathf.Clamp01(volume * AudioSettings.SfxVolume));
```

### 6.2 流式背景音乐

```csharp
clips = Resources.LoadAll<AudioClip>("Music");   // 只拿引用，不解压
```

> ⚠️ **大坑**：mp3 导入默认 `loadType = DecompressOnLoad`（解压进内存）。
> 一首 10 分钟 10MB 的曲子解压后约 **120MB**，同步加载会**卡住主线程好几秒**——表现为"连接服务器很慢"。
> **解决**：`loadType = Streaming`、`quality = 0.7`。

### 6.3 音量设置

`AudioSettings` 静态类 + `PlayerPrefs` 持久化，改动广播 `Changed` 事件：

```csharp
public static void SetMusic(float v) { MusicVolume = Clamp01(v); PlayerPrefs.SetFloat(...); Changed?.Invoke(); }
```

## 7. 网络与后端

### 7.1 客户端

```csharp
using (UnityWebRequest req = UnityWebRequest.Get(BaseUrl + "/health"))
{
    req.timeout = 2;
    req.certificateHandler = new TrustConfiguredHost();   // 自签名证书
    yield return req.SendWebRequest();
}
```

**多端点轮换**：`server.txt` 每行 `地址|密钥`，连不上就切下一个。

```
http://127.0.0.1:8000|change-me
https://xxxx.vicp.fun|change-me
```

### 7.2 服务端（PowerShell HttpListener）

```powershell
$listener = New-Object System.Net.HttpListener
$listener.Prefixes.Add("http://+:8000/")
while ($listener.IsListening) { $ctx = $listener.GetContext(); ... }
```

路由：`/health`、`/config`、`/notice`、`/scores`（GET/POST）。

### 7.3 反作弊基础

| 手段 | 实现 |
|---|---|
| 校验和 | `SHA256(name|score|wave|kills|secret)` |
| 范围检查 | 分数 0–1000 万、波次 1–9999 |
| 一致性 | `score <= kills × 500` |
| 名字 | 截断 16 字符 |

### 7.4 热更新设计

```json
{ "version": 19, "leaderboardLimit": 100, "maxFinalSpeed": 13.0, ... }
```

| 能热更吗 | 内容 |
|---|---|
| ✅ 改 JSON 即可 | 公告、配置（64 字段）、排行榜数据 |
| ❌ 必须重新打包 | 技能、UI、场景、代码 |

**铁律**：`JsonUtility` 会**忽略客户端不存在的字段**。
→ 新增字段 = 老包永远读不到 = **必须重新打包一次**。

### 7.5 编码血泪史

| 坑 | 现象 | 解决 |
|---|---|---|
| `.ps1` 无 BOM | PS 5.1 按 GBK 解析 → "缺少右 }" | 必须存成 **UTF-8 with BOM** |
| `.bat` 用 LF | "不是内部或外部命令" | 改成 **CRLF + ASCII** |
| `ConvertFrom-Json` | 数组被压成单个对象 | 改用 Python 处理 JSON |
| `scores.json` 被删 | 排行榜清空 | 备份 + `LB_DB` 环境变量 |

> **每次改完 .ps1 都要验证**：
> ```powershell
> $e=$null; [System.Management.Automation.Language.Parser]::ParseFile($f,[ref]$null,[ref]$e)
> ```

## 9. 常见坑总表

| # | 坑 | 现象 | 解决 |
|---|---|---|---|
| 1 | `Destroy(collider)` 延迟生效 | 子弹凭空消失 | 先 `enabled = false` |
| 2 | Outline 描边 | 文字发虚 | 正文关掉 |

| 7 | 编辑器脚本强制写值 | 面板调好的参数被刷回 | 只在"新建组件"时写 |

| 9 | 局部变量命名解析失败 | `tickInterval` 是实例字段 | 加对象前缀 |
| 10 | 负缩放 | Collider 翻转报警告 | `localScale = Vector3.one` |
| 11 | 相机空间画布遮挡 | HUD 盖住菜单 | `canvas.enabled = State != Menu` |
| 12 | 头像/血条朝向相机 | 俯视视角下立起来 | 保持 `Quaternion.identity` |

## 10. 教程：想复刻的话，按这个顺序

### 阶段一：最小可玩（1 天）

1. 相机俯视（位置 (0,11,0)，旋转 X=90）
2. 挡板左右移动（Input System）
3. 子弹：`Shoot` 定时发射 + `BulletPool` 对象池
4. 砖块：`BrickField` 定时生成，`Brick` 受击掉血
5. 失败线：`pos.x <= deadlineX` → GameOver

### 阶段二：手感（1 天）

1. 屏幕震动 `ScreenShake`
2. 击中火花 `CombatFx.HitSpark` + 对象池 `FxPool`
3. 伤害数字 `DamageNumber`（封顶 20 个）
4. 击杀碎片 `Shatter`

### 阶段三：Roguelike 循环（2 天）

1. `GameManager` 状态机（含 `UpgradeSelecting`）
2. `PlayerStats` 技能等级字段
3. `UpgradeDatabase` 抽卡 + 文案
4. UI 三选一面板（支持 1/2/3 和鼠标点击）

### 阶段四：表现升级（2 天）

## 11. 学到的工程思维（比技术更重要）

1. **先测量再优化** —— F1 面板指出 852 个渲染器，比猜半天有用
2. **数值外置** —— 所有手感参数进 config，调参不用重新打包
3. **给游戏装安全带** —— 看门狗（三选一面板卡死自动恢复）、多层兜底（子弹过滤特效碰撞体）
4. **写文档和备份** —— `scores.json` 被删过一次，之后所有脚本都带备份
5. **分清"能热更"和"必须重打包"** —— 新增字段的边界决定了发版节奏
6. **UI 遮挡要系统性检查** —— 列出层级表 + 三个问题（盖住谁/被谁盖/后面能不能点）
